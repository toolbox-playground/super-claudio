# Voiceover — ElevenLabs, validated settings

The narration is generated by ElevenLabs from a voice the user cloned from their own
recordings. This is the route that worked; `open-source-alternative.md` records why the
free local route was abandoned, with measurements.

## Validated configuration

These settings were tuned by the creator against their own cloned voice and approved by
ear. Treat them as the default and change one at a time.

| Setting | Value | Why |
|---|---|---|
| Model | **Eleven v4** (`eleven_v4`) | 10,000 characters per request, 90+ languages |
| Voice | the user's own cloned voice | ask for the voice name; never guess one |
| **Similarity** | **100%** | maximum fidelity to the cloned timbre — this is the point |
| **Stability** | **50%** | keeps delivery varied; higher flattens, lower wanders |
| Speed | 1.0 | adjustable 0.7–1.2 if the delivery drags or rushes |
| Language | Auto | the script's own language is detected |
| Output | MP3 | what the video pipeline loads |
| Audio effects | none | any effect changes the timbre that similarity 100% is preserving |

**Similarity at 100% is deliberate.** Voice identity is the whole reason for cloning;
the earlier open-source attempts failed precisely on identity. Do not lower it to
"clean up" an artifact — fix the text or the speed instead.

**Stability at 50% is a middle setting with a real trade-off.** Raising it makes
delivery more consistent and more monotone; lowering it makes it more expressive and
less predictable across a 60-lesson course. 50% was chosen for course narration, where
consistency between lessons matters.

## Settings per delivery mode

`narration-script.md` defines the three delivery modes. They want different settings.
The e-learning row is the measured, approved one; **the other two are starting points
to tune by ear, not measurements.** Change one value at a time and listen.

| Mode | Stability | Speed | Why |
|---|---|---|---|
| **e-learning** | **50%** (validated) | 1.0 | consistency across dozens of lessons matters more than peak expressiveness |
| conversational | try 40% | 1.0–1.05 | more variation and a touch more pace reads as talking rather than presenting |
| how-to | try 60% | 0.95–1.0 | steady and slightly slower, so a viewer can follow along while doing it |

Similarity stays at 100% in every mode. It is the voice identity, not a delivery knob.

## The recording script shapes the clone

This is worth knowing before cloning a second voice, because it is not obvious:
**"the speaking style in the samples you provide will be replicated in the output."**
ElevenLabs recommends one consistent style per voice, and professional cloning wants
at least 30 minutes of audio, an hour or more preferably, ideally close to three hours.

Their sample recording scripts are documented in three categories — **narrative,
conversational and advertising** — and the web UI additionally groups educational use
cases (how-to, tutorials, e-learning). You can also upload your own script.

The practical consequence:

- A voice cloned from **teaching** audio performs e-learning and how-to narration
  naturally, and sounds slightly formal when handed a loose conversational script.
- A voice cloned from **conversational** audio does the opposite.
- If the user produces both paid course lessons and casual YouTube content and cares
  about the difference, the highest-fidelity answer is **two cloned voices**, each
  recorded with the matching script category. One voice plus a register and settings
  shift is the cheaper answer and is usually good enough — try it first.

Two things the clone copies that are not style: **background noise and recording
artifacts**. A reference recorded in an untreated room produces a voice with that room
in it, on every lesson. And training audio must be spoken, never sung.

## Model limits

| Model | Characters per request |
|---|---|
| **Eleven v4** | **10,000** |
| Eleven v3 | 5,000 |
| Eleven Multilingual v2 | 10,000 |
| Eleven Flash v2.5 | 40,000 |

At ~1,200 characters per minute of pt-BR narration, 10,000 characters is about
**8 minutes of audio in a single request**. A 2–5 minute lesson is 2,400–6,000
characters, so **one lesson is always one request**. There is no need to split a lesson
for the model's sake, and splitting is undesirable: two requests mean two takes, and
takes do not match seamlessly.

Eleven v4 does **not** support SSML break tags. Pauses come from punctuation —
see `narration-script.md`.

## Three ways to generate, in the order to adopt them

### 1. Copy and paste in the web app — start here

For the first lessons, the user pastes `narration/aula.txt` into the ElevenLabs web app
themselves, generates, listens, and downloads the MP3. This is slower per lesson and
deliberately so: it is how the settings get tuned against the user's own taste before
any of it is automated. Produce the script, hand it over, and wait for the audio.

Ask the user to drop the download at `<lesson-dir>/audio/aula.mp3` and tell you when it
is there. Do not proceed to the video on an assumed filename.

### 2. The API — once the settings are settled

Standard text-to-speech returns audio only. The endpoint worth using instead is
**`POST /v1/text-to-speech/{voice_id}/with-timestamps`**, which returns the audio plus
character-level timing:

```json
{
  "audio_base64": "...",
  "alignment": {
    "characters": ["O", " ", "H", "P", "A", ...],
    "character_start_times_seconds": [0.0, 0.07, 0.12, ...],
    "character_end_times_seconds":   [0.07, 0.12, 0.19, ...]
  }
}
```

This matters more than it looks: those timings are **exact**, so captions and diagram
reveals land on the right frame. The estimated alignment used for a web-app download
drifts on long pauses. If the user cares about tight sync — and sync is the product —
this endpoint is the reason to move off copy-and-paste.

Timestamps are API only; the web app does not expose them.

### 3. MCP — when the user wants it driven from the conversation

ElevenLabs ships an MCP server. The hosted endpoint is
`https://api.elevenlabs.io/v1/mcp` and uses OAuth; the older local server
(`uvx elevenlabs-mcp`, key in `ELEVENLABS_API_KEY`) is deprecated in favour of it.

**Credential handling, not negotiable:** the API key is the user's. Read it from the
environment, never write it into a file in the repo, never echo it, and never ask the
user to paste it into the conversation. If no key is present in the environment, say so
and stay on the copy-and-paste route — do not block the lesson on it.

## After the audio exists

Measure before building anything on it:

```bash
ffprobe -v error -show_entries format=duration -of csv=p=0 audio/aula.mp3
```

Then check integrity, because a bad take renders into a perfectly valid-looking video:

| Check | How | Fail means |
|---|---|---|
| Real duration | ffprobe vs. the character budget | wildly short = truncated generation |
| Truncation | listen to the last 3 seconds / check the tail is not mid-word | regenerate |
| Silence holes | `silencedetect=noise=-35dB:d=1.0` | a hole over ~1.5s mid-lesson is a defect |
| Clipping | `volumedetect`, `max_volume` should be below 0 dB | regenerate or lower output gain |

A lesson that fails any of these gets regenerated, not patched. Never apply a limiter
or `loudnorm` to fix a level problem — compression flattens consonant transients and
the voice goes muffled. Use plain gain if a level change is genuinely needed.

## Cost, so a course can be budgeted

Credits are charged **per character**, and the measured rate is ~1,200 characters per
minute of audio. Cost per hour of finished narration, by plan:

| Plan | US$/month | included audio | **US$/hour of audio** |
|---|---|---|---|
| Starter | 6 | ~25 min | 14.40 |
| Creator | 22 | ~101 min | 13.09 |
| Pro | 99 | ~500 min | 11.88 |
| Scale | 299 | ~1,500 min | 11.96 |

A 4-hour course is about **240 minutes of audio**, so roughly US$ 50 of credits spread
over however many months it is produced in. Professional voice cloning starts on the
Creator plan; instant cloning is available from Starter. Credits are a single pool
shared across all ElevenLabs products, so generating music or dubbing eats the
narration budget.

Tell the user the character count of a module before generating it, so there are no
surprises mid-course.
